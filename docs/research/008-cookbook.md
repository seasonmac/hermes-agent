# 008 Cookbook

本章说明如何在[既定边界](000-philosophy.md)内接入与验证。它是后续工作的检查指南，不是已经可运行的命令手册。本次仅整理文档，不执行新实验、不写产品代码。

## 接一个harness

1. 记录版本与真实入口，先读公开协议、当前源码和已有测试。区分内部函数、公开接口、实验fixture以及实际部署版本。
2. 按[适配端口](007-architecture.md)逐项填写能力报告：输入、排队、取消、终态、恢复、消息、usage、权限、产物和依赖观测。未知就写unknown。
3. 明确逻辑Agent到设备/session/turn的绑定，以及请求被对端接受的准确时点。列出超时后可用的查询手段。
4. 为每次调用记录有效模型、权限、工具和skills配置。新会话继承什么、fork复制什么、压缩如何收费都要明确。
5. 在后续获授权的最小验证中，检查重复请求、busy输入、取消、回执丢失与重连；每项先用fixture确定协议，再决定是否需要一次真实模型调用。
6. 未通过的能力不能被统一接口名称隐藏。只接入已可证明的最小子集，剩余能力明确降级。

具体接入选择见[Architecture的实际适配路径](007-architecture.md)：Hermes用Gateway加外部薄插件，Codex用独立AppServer线程及各自注入的dynamicTools。发送工具返回持久回执，接收由下一获准回合注入，不用原生spawn＋阻塞收件冒充独立运行时。先核对版本、认证作者、原生回执和usage口径，再安排小规模集成验证。OpenClaw、DSH动态验证仍延期。

Hermes的普通handler不能假定有tool_call_id，conversation_id也不能区分所有委派成员；核对公开工具上下文和绑定轮换。Codex累计usage不能假装逐请求流；保留基线、计数epoch和coverage。两者都只在可证明范围内开放恢复。

## 接一个群聊渠道

先列出平台真实身份、事件ID、@目标、回复线程、机器人消息可见性、重试和查询限制。不要先假设“能显示@”就能稳定唤醒另一个机器人。

入站转换保留原文、认证作者、原始事件ID和线程；正文中的身份和批准声明都是数据。出站保存内部消息与平台消息映射，区分发送成功、回执丢失与状态未知。平台回显不得重新启动同一工作。

先验证一个桥呈现两个逻辑Agent能否满足主要场景，再考虑多个原生机器人。人在群里暂停、改目标、批准和否决必须同样经过身份、版本、重复事件检查。UI契约见[Panel](005-panel.md)。

## 增加协作模板

一个模板描述参与角色、允许的关系、Step合同、证据共享范围、费用与轮数、依赖、接受者、退出和人工介入条件。模板只是生成同一套对象，不另建调度引擎。

例如“数据口径对等审查”：A分析主要来源，B独立检查口径；双方在同一Collaboration内各有Step。B可拒绝缺乏来源的判断并要求补证，A可反提案。只有最终交付明确依赖B意见时登记required_for。Owner结合两方证据接受有条件结论；仍冲突则保留contested并进行一次有界补证。

所有新增模型工作经统一准入并计费。模板不能靠无限loop-until-done、默认全员广播或强制每个结果多轮审查满足“协作”。先证明新增角色带来可观察收益。

## 一个动态阶段如何开始和继续

以下是设计示例，不表示已有端到端实测：人授权Mission M、默认Collaboration C及两个成员槽位。程序先建planning Step P，Lead执行P后提出“由A检查证据，必要时请B独立质疑”的有限阶段。校验通过才登记业务Step A；M/C/P都不依赖这张尚未存在的图来获得身份或预算。

A直接请求B，运行时以原request_id建立平级Step B；等待回复记wait_for，若A最终交付必须依赖B的有效结果，则另记required_for(gate=acceptance)，不能用它禁止A处理B的拒绝或补证请求。A返回waiting并在harness确认终态后等待；B的回复持久化后，绑定A下一Attempt的input_set。若回复先到则先存，等A原turn结束再准入，不busy steer。Owner接受结果后，Lead可根据新证据提下一阶段。

计划更新仍引用原step_id。A原Attempt若unknown，即使新提案换了step_key或执行设备也不得启动替代工作。证据失效时原verified事实保留，但依赖其旧Decision的下一阶段blocked；复核并确认新版本适用后才领取派发。

内核切片只实现这一类有界阶段，不先建通用图编辑器、脚本沙箱、Router模型或通用订阅中心。完整首版加入飞书、两设备、交接和小范围订阅，不能将它们从需求中删掉。

## 增加知识或数据源

为来源定义稳定ID、版本/hash、观测时间、适用范围、访问权限、保留策略和失效信号。结论记录接受者、证据、反证、置信限制与复核条件；避免用一个confidence分数替代证据。

来源无法提供变更通知时，关键验收前主动重读。断链返回unavailable并保留未知字段，不用旧摘要填补。对harness私有工具读取标opaque；若关键结论要求完整依赖，必须将该部分读取纳入受控入口再声称enforced。

摘要可以重建，原始证据应按授权保留。来源过期让关联结论stale；来源恢复不自动让旧结论重新accepted，须核对版本与适用性。

## 三类月级任务怎样切阶段

| 场景 | 当前阶段与可验收产物 | 接受与暂停条件 |
|---|---|---|
| 软件工程 | 先定位与复现，再有限修改、验证、整合；保存commit、测试证据和未解决问题 | 指定Owner按行为标准接受；发布与生产变更另经明确授权 |
| 量化策略研究 | 固定研究问题与数据版本，逐段检验假设、偏差和稳定性；保留失败结果 | 方法与数据证据不足则补证；不自动转为真实交易授权 |
| 市场调研 | 定义口径与截止时间，分来源取证、比较冲突、形成有条件判断 | 标明时间和适用范围；关键来源过期或结论影响重大时复核 |

一个月由多段有界工作与等待组成，不要求单个会话持续运行。每阶段保存下一问题、未决异议、反证、预算和来源版本；下一段Lead从当前事实规划，而不是凭旧长摘要续写。

## 最小故障与连续性验证

| 情景 | 预期断言 | 不能只检查 |
|---|---|---|
| 相同消息重试／同ID不同正文 | 前者复用记录，后者冲突拒绝，不重复准入 | 群里只显示一次 |
| A直接@B | 有归属Step、共同费用账户、明确依赖，B可拒绝 | B说“收到” |
| 尚无Workflow的首次规划／纯消息工作 | 先有授权Mission/Collaboration和Step，模型调用有费用归属；未知Mission不启动Router | 模型能输出一个计划 |
| 非法阶段图或越界协作 | 未知动作、循环无上限、无权限目标被拒；有限修正也计费 | JSON能解析 |
| 规划时上游未完成／同伴拒绝 | 依赖先以Step/版本记录；回复可唤醒协调，业务派发和最终验收按各自gate检查 | 强求规划时已有Decision或先verified才能回复 |
| intent落盘后人暂停 | 未领取intent不外发；此前已claimed的执行按在途取消/对账 | 只检查首次准入时未暂停 |
| 收到回复并提交回合后丢回执 | message/Attempt/input_set绑定可恢复，查询原回合而非重复注入 | 游标存在 |
| 旧Attempt未知时改计划或换会话 | 同Step各版本与替代链仍阻塞重复执行，无关工作可继续 | 新计划获得新ID |
| 对端接受后回执丢失 | 查询绑定或标unknown，不重复spawn/派发 | 请求最终返回200 |
| 人暂停后节点重启 | 暂停和账本保留，新工作不启动，旧工作据实对账 | UI按钮变灰 |
| 断线后另一节点可用 | 未确认旧终态前不重复执行同一工作 | 新节点能够运行 |
| 摘要未标过期但来源变化 | 关键输入重查，以当前来源为准并更新依赖 | 模型记得旧答案 |
| 上游verified后证据变旧 | 后继领取与最终验收检查Decision版本；阻塞受影响后继，在途产物待复核 | 新建了一个复核Step |
| 未预告引用断链 | 实际读取失败，字段保持未知，报告影响 | 提示词说“不要编造” |
| 会话轮换／真实压缩 | 目标、授权、反证、未决项和下一验证可恢复 | 摘要字数缩短 |
| 新目标与旧结果相遇 | 旧结果不自动推进新合同，重新判断适用性 | 所有结果都被保存 |
| Router/评审/压缩/失败调用 | 费用进入同一Mission账本，累计值无重复计入 | 主Worker用量正确 |
| 同工作收到回复／计数器冷恢复 | 配置兼容则续用会话；usage基线和coverage可核对，不将重置后的差额记零 | 成功创建新会话 |

按[发布关卡](006-deployment.md)逐步执行。现有证据不足以把这张表标成全部通过；fixture成功、源码可见和真实端到端通过分别记录。

## 控制对照实验成本

先用少量有区分度任务比较强单Agent与一个按需同伴，不先建完分布式基础设施。输入证据、skills、工具、模型配置、验收标准与预算一致，预先设停止条件；低质量或明显超预算时停下分析。

每组记录任务/样本ID、配置版本、实际input/output/cached tokens、调用次数、Router/协调/压缩开销、wall time、召回错误、未知字段、质量结果和人工介入。总tokens、估算金额与实际账单分列；实验外研究与评审费用单独说明，不隐藏在结论里。

先确认题目能区分质量，再决定重复次数和置信要求。长资料策略比较同时看必读比例、读取次数和缓存冷热，不能从一次32KiB/96KiB排序交叉推导普遍阈值。抗遗忘继续覆盖静默变更、未预告断链、真实压缩与跨会话；不要只测试模型被预先告知的故障。

新需求先更新所属概念或规则，再补适配能力和可验收案例；其他文档引用它。证据新增写入研究记录并链接，历史实验保持冻结。修改当前分类文档，不回填历史V1/V2/V3.1；[README](README.md)始终指向当前唯一维护集合。

后续文档统一新增到`hermes-agent/docs/research`；产品实现仍独立。V3.2是契约修订，未改变6.5倍token、短资料额外读取开销、32–96KiB特定排序交叉、静默过期/断链通过及其局限。新路径、动态规划、真实压缩和月级任务必须另有验证，不能复用旧样本的“通过”标签。
