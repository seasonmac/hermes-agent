# 008 Cookbook：怎样逐步接入和验证

本章把前面的规则放进具体工作中：先核对适配能力，再走通一个有界协作场景，最后增加故障和长程验证。它是后续工作的指南，实际运行还需要对应实现和验证记录。

## 接入一个 harness，从最短链路开始

先记录实际安装版本、启动入口和配置，再核对公开接口。源码提交、安装二进制、存活服务可能不同，不能相互代替。能力表逐项填写输入、busy、取消、终态、恢复、消息、费用、权限及来源观测；没有证据就保留 `unknown`。

接着确定可信身份链：逻辑 Agent 如何绑定设备和会话，一次原生回调如何关联 Attempt，请求何时被对端接受，丢回执后能查询什么。每次探针固定实际模型、工具、skills 和权限，避免在比较过程中悄悄改变条件。

优先用零模型 fixture 验证协议。T0-P 已完成部分工作，下一步应补缺口，而不是重复全部历史测试：

| 路径 | 可以复用的证据 | 下一项最小验证 |
|---|---|---|
| Hermes | 公开加载器可加载插件；候选配置可生成最小直接工具表；合成身份和公开拒绝钩子可工作 | 先核对完整派发权限，再在获准的正常 Gateway 回合验证身份到 Attempt 的绑定及持久 send 回执 |
| Codex | 安装版 AppServer 动态回调及终态后同目录冷恢复 | 核对剩余内置工具的执行权限；将原生回调接到持久业务输入与回执 |
| 两者的费用 | Codex 合成累计计数可延续 | 另作获准的最短真实用量探针，覆盖主调用与辅助调用，不用合成计数推算成本 |
| 在途恢复 | 设计有处置规则，尚无该路径通过证据 | 单独注入接受后丢回执、待决工具回调和尾账窗口；不能复用终态后恢复标签 |

具体接口见 [007](007-architecture.md#adapters)。Hermes 普通 handler 不自带 tool_call_id；Codex 累计用量也不是逐请求流水。只在已经证明的范围开放能力。OpenClaw、DSH 动态接入继续延期。

## 走通一个动态阶段和一次直接协作

继续市场研究示例，人授权 Mission M、协作范围 C 和两个固定成员槽位。程序先建立规划 Step P，Lead 才提出“由 A 整理数据，遇到口径问题请 B 核对”的有限阶段。P 的身份和费用不依赖尚未生成的计划。

提案通过授权、动作和预算检查后，运行时登记 A 的工作。A 发现统计日期不一致，直接发送请求给 B。原文持久化后，B 的平级 Step 归入 C，共用协作额度；不必把 B 挂成 A 的子执行，也不要求 Lead 转述。

A 用 `wait_for` 等回应。这里假设合同已经要求独立口径审查，因此初次登记 A 时就保存了指向 B 审查工作的 `required_for(gate=acceptance)`；A 现在发出的是落实该义务的请求。B 可以说“缺少第二份来源，请补齐”，A 仍能处理这条回复；但补证对话不能自行消除最终审查要求。

如果独立审查是执行中才提出的新要求，则先按依赖变更规则批准并生成 A 的新 Step 修订。旧回合仍按原版本对账，其产物另判适用性；新修订的后续输入显式关联原请求和回复，不能直接修改旧修订。

A 返回等待说明并结束回合。回复早到就先存入收件箱，晚到就唤醒等待；两种情况都等原回合终态后，经准入提交下一份 input_set。结果由合同指定的接受者验收，Lead 再据当前证据提出下一阶段。

在这一场景中，至少检查三种变化：

- Lead 想删掉 B 的门槛时，程序比较依赖变更及授权；删除计划节点不能解除独立审查义务。
- A 的提交回执丢失时，先查询原 Attempt；换计划、会话或设备都不能绕过未知执行处置。
- 来源后来过期时，保留原验收历史，阻塞依赖旧 Decision 的新派发，并对在途产物要求复核。

内核切片只需这一类有上限的阶段及双成员协作。通用图编辑器、任意脚本沙箱、模型 Router 和订阅中心不必提前建设；完整首版再兑现飞书、两设备、交接和小范围订阅。

## 怎样处理一次无法查明的执行

假设回执丢失后，原会话也无法查询。先显示最后已知状态、原输入、已经尝试的查询和仍可能发生的费用。人可继续查询、提供停止或隔离证据，或放弃业务。

若证据能排除旧执行继续产生新调用及相关副作用，具名有权者可批准有限处置。记录原 Attempt、证据和允许解除的阻塞，退役旧绑定，再为重试建立新绑定。原 Attempt 可以继续为 `unknown`，旧输入消费及费用记录仍在。

如果费用尚未查清，则继续占住预约；只有存在可验证上界时，才能转换为仍扣减可用额度的费用准备额。既无法界定执行风险，也无法界定费用时，不新增受影响范围内的工作。放弃业务可以结束交付义务，不能消除这些未知事实。完整合同见 [003](003-execution.md#unknown-disposition)。

## 接入飞书群，先验证真实事件语义

先列出平台作者、事件 ID、@ 目标、线程、机器人消息可见性、查询与重试能力。现有 @ 补丁提供局部依据，正式接入仍需核对平台实际事件，不能从“群里能显示 @”推导可靠唤醒。

若采用一个桥接机器人，先验证它能否清楚呈现两个逻辑成员及其原文回复；选择多个原生机器人时再验证机器人之间的事件限制。入站保留认证作者和原事件，出站关联内部与平台消息 ID，回显不再次启动工作。

人的批准、否决、暂停和改目标绑定提案与对象版本，按同一套控制规则处理。飞书故障时，受认证管理入口仍能控制任务。显示语义与未知发送处理见 [005](005-panel.md)。

## 增加协作模板或来源

协作模板描述角色关系、Step 合同、共享范围、预算、往返数、依赖、接受者和退出条件。它生成同一套对象，不引入第二个调度引擎。新增角色应解决明确问题，例如独立检查统计口径；不能仅为了展示“多个 Agent 很忙”而默认广播和反复审查。

新来源需要稳定身份、版本/hash、观测时间、适用范围、权限、保留策略和失效信号。结论保留依据、反证、接受者和复核条件，confidence 分数不能替代这些记录。

关键来源没有变更通知时，在重要验收前主动重读。未预告断链应产生 `unavailable` 和影响说明，不用旧摘要补全未知字段。黑盒工具读取标 `opaque`；只有指定范围确实强制经过受控工具时，才声明该范围 `enforced`。来源恢复可读后，旧结论仍需核对版本和适用性。

## 三类月级任务怎样组织

| 场景 | 有界阶段与产物 | 接受或暂停依据 |
|---|---|---|
| 软件工程 | 定位与复现、有限修改、验证、整合；保留 commit、检查证据及未解决项 | 交付负责人按行为标准接受；发布和生产变更另需明确授权 |
| 量化策略研究 | 固定问题与数据版本，分段检验假设、偏差及稳定性；保留失败结果 | 方法或数据证据不足时补证；研究授权不自动成为真实交易授权 |
| 市场调研 | 明确口径与截止时间，分来源取证、比较冲突、形成有条件判断 | 关键来源过期或结论影响重大时复核，保留范围和时间限制 |

一个月由多段执行、检查点和等待组成。每阶段留下证据增量、已排除路线、未决异议、费用和下一项验证。连续没有实质进展时触发有界诊断，再交人选择，而不是继续累积消息。

会话兼容则续用，实质目标或权限变化时按 [004](004-prompts.md#session-reuse)轮换。每次恢复都读取完整当前目标和必要原始证据，摘要只作索引。真实压缩、跨会话及 30 天连续性仍分别需要验证。

## 用故障场景检查合同是否完整

这些是待执行的验收场景，不能因规则已经写出便标为通过。测试记录必须区分源码依据、fixture 和真实端到端运行。

| 场景 | 应看到的结果 |
|---|---|
| 同消息重试；同 ID 不同正文 | 复用原记录；内容冲突拒绝，不重复准入 |
| 首次规划尚无 Workflow；纯消息产生工作 | 先有授权 Mission/Collaboration 和 Step，每次调用都有费用归属 |
| 非法动作、无限循环、未授权成员 | 提案被拒，有限修正仍计费 |
| 上游未完成；同伴拒绝或要求补证 | 依赖可先待绑定；回复允许协调，派发与验收门槛分别检查 |
| 删除、重指或放宽独立审查依赖 | 检查原义务及变更权限，不因换图或新 Step 消失 |
| intent 已落盘后人暂停 | 未领取意图不外发；此前已领取的执行进入取消和对账 |
| 回复先于原 turn 终态到达 | 先存回复，终态后至多准入一次，不 busy steer |
| 提交 input_set 后丢回执 | 恢复消息消费与原 Attempt 关联，先查询原回合 |
| 旧执行未知时换计划、会话或设备 | 替代链仍受约束；无关工作可以继续 |
| 原结果丢失但存在充分停止或隔离证据 | 独立保存处置、退役绑定和重试引用；未知费用继续占额度 |
| 处置后同一 Step 修订开始重试，旧结果迟到 | 原 Attempt 只补历史与费用；复用产物另需明确决定，不推进当前执行 |
| 复核解除阻塞，原产物或等待仍在 | 继续验收或恢复原等待；仅需新执行时转 ready |
| 人放弃业务，后来收到费用或结果 | 业务保持取消；对账原 Attempt，不自动重开或删账 |
| 取消请求被接受但未确认终态 | 保留在途占用，不把“请求成功”当作“停止成功” |
| 暂停后重启；节点断线后重连 | 恢复暂停、授权、预约和旧回执，先对账再准入 |
| 摘要未标过期但关键来源变化 | 主动核验发现变化，使已知下游依赖失效 |
| 上游已 verified，后续来源失效 | 保留历史验收；阻塞未派发后继，在途产物须复核 |
| 未预告断链；来源后来恢复 | 缺失保持未知；重新可读不自动恢复旧结论效力 |
| 人实质改变目标，旧结果迟到 | 关联旧合同，另判对新目标的适用性 |
| 真实压缩或换会话 | 目标、权限、反证、未决项及下一验证可恢复，绑定变化可追溯 |
| Router、审查、压缩、失败与尾账 | 同一 Mission 记账，保留 coverage，累计与明细不重计 |
| 同工作收到回复；用量计数器冷恢复 | 兼容则续用会话；核验基线及 epoch，缺口不能记零 |

按 [G-A～G-E](006-deployment.md#gates)分批执行。优先证明关键合同，再扩展真实渠道和两设备，不先堆满模板与治理角色。

## 质量对照怎样控制成本并保持公平

已提交[实施计划](2026-11-16-kernel-slice-implementation-plan.md)预留 36 万模型实验 tokens 软预算，并把最短适配探针前移。这是整个实验计划的预算，不是每组额度，也不是提供方保证的硬限。T0-P 的合成计数不消耗或替代这份真实实验预算；研究助手和文档评审消耗单独说明。

首次对照沿用 T1 的小规模安排：一份不超过约 24 KiB 的合成资料，强单 Agent、一次审查、有界对等协商各运行一次。三组共用预先冻结的模型、证据、skills、权限、工具和 8 项评分标准。默认每组上限 B=50,000 tokens；若最短探针表明需要调整，必须在任何评分结果出现前，对所有组统一冻结预算矩阵。

开跑前先检查三组的最短路径是否都能容纳于共同额度；任一组不可行就报告预算设计问题，不先运行注定缺步骤的比较。各组使用相同的新会话条件，不继承前组解题历史，并记录实际缓存冷热。

三组最大业务回合数依次为 2、3、4，内部模型请求数另外统计。各组使用相同总预算并不要求相同回合数；协作产生的请求、续跑、审查和协调都算进本组额度。强单 Agent 允许合理自审，不通过缺工具、少资料或限制自审人为削弱基线。

计分采用预算内最后一个已完成、已结算且可归属的产物。用量延迟时等尾账后再判断；只有整回合用量时，以整个回合结算为准，不倒推虚构分项。越界后产生的产物仅作探索观察；没有预算内合格完成产物则标 `budget_incomplete`，不把它伪装成内容质量 0 分。费用无法可靠归属的样本标为 `cost_unknown`，不进入公平质量与成本比较；安全与授权错误也单独记录。

若强单 Agent 已取得 8/8 且无安全问题，说明本题缺少区分度，停止其余组以节省预算，结论写“饱和，未能判定协作收益”。若质量相同而协作更贵，收缩默认协作策略。**这两种结果均不阻止 G-A/B 内核验证。** 人工指定或合同要求的独立审查仍保留。

每组至少记录以下信息，以便解释差异：

| 类别 | 记录内容 |
|---|---|
| 配置 | 样本 ID、模型和工具/skills 版本、权限、证据 hash、预定预算 |
| 消耗 | 实际 input/output/cached tokens、调用与回合数、规划/审查/压缩/失败分项、覆盖缺口 |
| 质量 | 分项得分、召回错误、未知字段处理、可定位的产物与证据 |
| 运行 | 耗时、人工介入、超额、终止原因及未对账费用 |

总 tokens、估算金额和实际账单分别报告。一次小样本只能决定是否值得继续调查，不能给出普遍质量优势或统计显著性。扩样前预先定义所需收益与可接受成本，不看到结果后再改标准。

历史 G2 的 6.5 倍消耗同时存在题目满分和技能配置混杂，不能当作多 Agent 的固定成本倍数。短资料额外读取开销、32/96 KiB 特定排序交叉、静默过期与断链小测支持的策略及其限制见 [004](004-prompts.md#context-evidence)。这些结果保留，不能替真实压缩和月级运行验收。

## 文档和证据怎样继续维护

新规则在所属章节定义，其他章节引用；适配证据写入版本固定的研究记录，再更新能力表。历史实验及 V1/V2/V3.1 保持冻结，不因规范变更回填“已通过”。

后续实现开始前，应以当前合同校准实施计划中的相应任务与验收项。[研究入口](README.md)指向唯一维护集合及证据目录。
