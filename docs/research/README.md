# 独立协作运行时研究与设计

2026-11-16 · V3.2执行契约修订版 · 设计阶段，尚未实现。

这套设计面向软件工程、量化策略研究和市场调研：人通过飞书指挥多个Agent，在不同harness与设备上推进最长一个月的任务。运行时保存目标、授权、证据、消息、执行与成本，harness承担推理和工具执行。

以下九篇是当前设计的唯一维护入口。分类参考DSH原型的000–008文档，内容属于独立协作运行时。文档已迁入`hermes-agent/docs/research`，后续在这里维护；当前工作分支实际名为`multiAgent`。文档落在Hermes仓库不改变运行时独立模块、外部适配器的产品边界。旧单篇设计、源码研究和实验记录分别作为历史与证据保留。

## 首版与当前证据

第一个内核切片是单机、一个Mission/Collaboration、两个固定成员槽位，接Hermes与Codex，按需启用同伴，完成有界对等协商、直接mention、证据采纳、人工暂停、持久账本和重启恢复。完整首版再加入真实飞书、两设备、交接与小范围订阅；单机切片不能称作完整首版。OpenClaw/DSH实际接入延期。边界以[Philosophy](000-philosophy.md)为准。

dynamic workflow采用受限声明式阶段图：Lead提出计划，Router只判断归属，Worker执行并回报；校验、准入、等待、结果复用与恢复由运行时负责。角色能力可以承接这一分工，但现有实验没有验证完整动态规划闭环；任意代码工作流与全模板库延期。[能力与缺口](003-execution.md)

V3.2补齐：工作身份独立于计划版本、规划/路由启动归属、派发与暂停边界、逐Attempt输入消费证据、结论有效性门槛、会话复用和最小工具表，以及Hermes/Codex具体适配路径。它不增加新的实测结论。

| 已有结果 | 可以支持 | 不能据此声称 |
|---|---|---|
| 原G2双Agent总tokens为单Agent6.5倍，双方题目均满分 | 必须减少无效协作并校准费用口径 | 多Agent质量更优，或固有成本固定为6.5倍 |
| 四条件与基础召回小测共283,190 tokens | 已知归属直达；短资料内联有优势 | 稳定节省比例、月级抗遗忘 |
| 长资料与无预警召回8样本共186,885 tokens | 32KiB内联更省总量、96KiB按需更省；支持混合策略 | 通用32–96KiB阈值、金额转折或真实压缩可靠性 |
| Hermes原生接口与Codex公开通信有局部证据 | 适配器可以从已有入口逐项验证 | 跨harness完整闭环已通过 |
| 原生预算存在在途超额和冷恢复边界 | 外部持久账本与软停止必需 | 已实现严格金额硬限或月级无人值守 |

两轮上下文测试每条件一次、合成资料、缓存冷热未控制，召回检查并非独立盲评。总tokens不等于账单金额。研究助手与独立评审的消耗不包含在这些实验汇总中。
