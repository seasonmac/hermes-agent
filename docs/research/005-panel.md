# 005 Panel

首版以现有飞书群为主要交互场景。本章定义人和Agent看到什么、如何决策；不是要求先建完整Web产品。界面呈现[运行时记录](007-architecture.md)，不维护另一套任务状态。

第一个内核切片可以用本地受认证入口和可读事件记录完成同样的暂停/纠正验收，不开发独立Web面板；这只是中间切片。完整首版必须接真实飞书并验证作者、回复链、控制与去重，不能以本地日志替代群聊验收。

## 群聊里的直接协作

逻辑Agent有稳定名称与地址，消息显示实际作者、收件人、所属任务和回复引用。建议首版使用一个桥接机器人呈现多个逻辑作者，例如“A → @B”，由运行时完成寻址；这是直接逻辑通信，不需要另一个模型转述。

一个桥接机器人是建议默认，尚非用户确认的部署选择。如果使用多个原生机器人，则要单独验证平台对机器人消息、@事件、线程、去重和权限的限制。已有@修复只说明某一显示或投递路径得到修补，不能代替正式消息契约或证明飞书全链路已通过。

在群中呈现工作请求、接受/拒绝、反提案、关键证据、异议、验收和阶段决策。工具细节与普通状态变更默认折叠为引用；不展示内部思维链，也不把密集对话伪装成进展。

## 一段可见流程

| 群中事件 | 展示内容 | 运行时行为 |
|---|---|---|
| A请求B审查数据口径 | 作者、@B、工作目的、证据引用、任务标识 | 保存Message并准入同一Collaboration下的平级Step |
| B发现证据不足 | 缺口、反提案、必要读取范围 | 保存回复；按合同补证或交给Owner选择 |
| A和B结论不同 | 分歧、各自来源、对交付的影响 | 保留contested，不用多数票自动接受 |
| Owner接受有条件结论 | 接受者、版本、条件、复核触发项 | 写Decision，后续仅在适用范围复用 |
| 人暂停 | 暂停范围、生效状态、尚未确认停止的执行 | 关闭准入，取消在途，继续等待真实终态 |

可选查看详情包括完整证据、消息轨迹、费用分项和执行绑定。首版用群消息与可追溯记录即可，不以开发任务看板作为前置条件。

## 人的决策入口

每个需要人的请求都给出具体提案、对象版本、选项、后果和影响范围。批准、否决、改目标、暂停、恢复分别记录为认证决定；一般回复或被引用的文字不能冒充批准。

自然语言“可以”只有在唯一明确且仍有效的待决提案下才映射为接受，否则要求明确对象。群按钮只是可选交互方式，不能假定飞书按钮回调已经实现。无论文字还是按钮，都必须核验操作者身份、提案版本和重复回调。

改目标时显示新旧目标差异、受影响工作和产物、费用影响。程序先按授权规则处理暂停与取消，再接受新revision；旧执行的迟到输出显示为旧版本结果，不能自动满足新目标。

问题只阻塞它真正影响的分支。同一个待决问题不反复发送；无人响应不会自动批准、恢复或扩大预算。

## 状态文案必须准确

| 可显示 | 依据 | 避免的误导 |
|---|---|---|
| 已记录，等待派发 | journal已提交 | “B已经开始处理” |
| 接口已接收 | transport回执 | “B已读懂” |
| 已加入输入／历史 | 适配器可观测记录 | 把模型认知当成可验证状态 |
| 结果待验收 | 结果已持久化 | “任务已完成” |
| 暂停已生效，仍有执行待停 | 新派发领取已关闭；此前已领取/在途调用的取消终态未齐 | “所有工作都已停止” |
| 节点断线，执行状态未知 | 心跳或查询失败 | “任务失败，可立即重跑” |

群里看到消息只说明投影存在，不等于业务请求已完成。Message、Step与Attempt的状态定义以[Execution](003-execution.md)为准。

来源过期时显示“原验收保留，当前需复核”，并列受影响后继；不得仍显示“所有依赖满足”。计划改版显示原Step的续用/修订/替换关系和未对账执行，不把新计划当成清空旧状态。暂停详情区分未领取、已领取待确认、已确认停止，避免人误判控制效果。

## 通知与注意力

立即通知需要人决策的阻塞、预算到限、关键证据冲突、目标偏离和实际执行故障；已有提案更新原上下文，不重新制造多个待决项。阶段完成汇报产物与验收依据，而非仅汇报忙了多久。

建议默认提供有变化才发送的每日简报：目标与阶段、实质证据增量、已花费/在途费用、未知项、下一步、需要人的决定。每周复核目标是可选合同策略；这些频率尚未启用，也不是不可调整的要求。没有变化则保持安静。

人可随时查看任务当前状态，不必重读整个月聊天。最小概览含目标版本、Owner、暂停、进展证据、未决提案、费用、活动/未知执行与最近检查点。对外显示“成本未知”优于填零。

## 渠道一致性

入站消息用平台事件ID去重，内部作者来自认证映射。出站消息由持久outbox驱动，保存内部message_id与平台message_id映射；收到自己的回显只更新投影，不再次唤醒Agent。

平台发送超时可能已经成功，先查询或对账。若平台无法按客户端ID查询或去重，记录发送状态未知并限制重试；不能承诺群里绝无重复。编辑、删除、撤回的能力按平台实际声明，群消息删除不抹掉运行时审计事实。

通知可因平台限流延迟，执行事实仍以运行时为准。人工控制的认证、入站持久化与准入检查优先于普通通知；飞书故障时通过受认证的管理入口操作，不能靠在不可信正文里写“已暂停”。
