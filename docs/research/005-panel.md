# 005 Panel：人在群聊里怎样理解和控制任务

人查看群聊时，应能回答：现在在做什么、谁在负责、结论依据是什么、是否需要我作决定。界面展示运行时已经保存的事实，不维护另一套任务状态，也不以消息数量代表进展。

完整首版以现有飞书群为主要入口。内核切片先用本地受认证控制入口和可读事件记录，验证同样的暂停、纠正和对账语义；这个中间结果不能替代真实群聊验收。

## 让直接协作看得见

市场研究中，群里显示“A → @B：请核对这两份报告的统计日期”，随后显示 B 的原始回复、引用和分歧。运行时直接寻址，不需要 Lead 用模型转述。消息旁提供任务、工作项和回复链，便于人追溯上下文。

建议用一个桥接机器人呈现多个逻辑成员，部署选择仍为待定。逻辑作者和真实平台发送者应同时可辨识，不能把桥接展示伪装成多个平台身份。若采用多个原生机器人，需要另验机器人消息可见性、@ 事件、线程、权限与回显规则。

既有飞书 @ 补丁属于局部显示或投递证据，正式协议仍须验证身份、请求归属、唤醒与去重。工作请求、拒绝、反提案、关键证据、异议、验收和阶段决定在群中可见；普通工具细节折叠为引用，不展示内部思维链。

## 一段群内协作怎样呈现

| 事件 | 人看到的内容 | 对应运行时事实 |
|---|---|---|
| A 请求 B 核对口径 | 作者、收件人、目的、来源和工作项 | 原消息已记录；通过准入才执行 B |
| B 发现缺少来源 | 缺口和补证建议 | 保存回应，满足等待不代表满足验收依赖 |
| A 与 B 结论冲突 | 双方依据及对交付的影响 | 结论保持 `contested`，按合同安排补证或非争议方决定 |
| 接受者采纳结论 | 接受者身份、版本、条件、尚存限制 | 写入 Decision，后续在适用范围内使用 |
| 人暂停任务 | 暂停范围、生效状态、仍待停止的执行 | 关闭新领取，已在途执行继续取消与对账 |

交付负责人若是争议一方，界面不能提供让其直接清除争议的普通“通过”动作。需要展示合同指定的非作者接受者或人类决定入口，规则见 [002 知识采纳](002-authorization.md#knowledge)。

## 人怎样批准、否决和改目标

每个待决问题都有提案 ID、对象版本、具体选项、后果和影响范围。批准、否决、改目标、暂停、恢复是不同操作，分别核验身份与权限。一般回复、转发文字或 Agent 的“已获批准”不能形成控制决定。

自然语言“可以”仅在唯一明确且仍有效的提案下可解释为接受；其他情况要求明确对象。按钮可以简化交互，但不是必要前提。文字和按钮均需防止重复事件及过期版本操作。

改目标时先展示差异、受影响工作和预计费用。提交后，旧意图停止领取，在途工作按原 Attempt 取消或对账。迟到输出明确标为旧版本；新的目标是否可以采用它，需要另作适用性判断。

问题只阻塞真正依赖它的分支。相同问题更新原提案，不连续发送多个版本催人答复。无人响应时维持既有授权与暂停状态。

## 未知执行也要有可操作的说明

遇到断线，不只显示一个红色的“失败”。详情应列出最后已知回执、绑定对象、查询进展、仍可能发生的执行与费用，以及可以选择的下一步。

人可以继续查询、提供停止或隔离证据、批准有证据的处置，或放弃业务。界面同时解释各动作的效果：放弃报告不代表旧请求停止；允许接续不代表费用结清。没有充分证据时，不提供默认的“强制重试并清空费用”入口。具体要求见 [003 未知执行处置](003-execution.md#unknown-disposition)。

处置记录和待对账费用应在业务结束后仍可查看。迟到回执到达时，更新原执行并通知实际变化，而不是自动重启已放弃的工作。

## 状态文案以证据为准

| 显示文案 | 所需证据 |
|---|---|
| 已记录，等待派发 | 运行时事务已提交 |
| 接口已接收 | 有对端接受回执 |
| 已加入输入或历史 | 适配器观察到相应内容，并注明观察层级 |
| 结果待验收 | 产物已持久化，验收尚未完成 |
| 已暂停，部分执行仍待停止 | 暂停已提交，在途取消尚无全部终态 |
| 执行状态未知，正在对账 | 断线或查询失败，缺少可靠终态 |
| 业务已放弃，仍有未对账费用 | 业务取消决定已保存，旧费用尚未结清 |
| 原验收保留，当前需复核 | 历史验收存在，相关证据已失效 |

模型理解了什么无法从传输状态直接证明。群里有一条消息，也不能证明工作已完成。Message、Step 和 Attempt 的状态归属 [003](003-execution.md#step-states)，界面只投影这些事实。

来源失效时列出受影响的后继工作；计划改版时显示 Step 的续用、修订和替换关系；暂停详情区分未领取、已领取待确认和已确认停止。人应能看到变更的实际影响，而不必自己推导隐藏状态。

## 通知要帮助决策，而不是证明系统很忙

需要人作决定的阻塞、预算到限、关键冲突、目标偏离和实际故障应及时通知。阶段完成时汇报产物与验收依据，普通重复状态默认静默。

建议合同提供“有变化才发送”的每日简报，包含当前阶段、证据增量、已知和未对账费用、下一步及待决问题。每周目标复核可按任务需要启用。这些是可调整默认值，不是已部署的通知任务。

人可随时查看当前目标版本、交付负责人、暂停状态、进展证据、待决提案、活动及未知执行和最近检查点。费用不可靠时直接显示“成本未知”，不填零。

## 渠道故障时，控制事实仍然有效

飞书入站按平台事件 ID 去重，内部作者来自认证映射。出站使用持久 outbox，关联内部 message ID 与平台 message ID。机器人回显只更新投影，不再次唤醒 Agent。

发送超时可能意味着消息已经送达。适配器先按平台能力查询或对账；若无法按客户端 ID 去重或查询，保留发送未知并限制重试，公开重复展示的可能性。编辑、删除或撤回群消息不删除运行时审计事实。

平台限流可以延迟通知，但不能改变暂停与授权。认证后的控制输入优先持久化；飞书不可用时，人通过受认证的管理入口操作。另一条消息声称“已暂停”不能替代控制服务的确认。
