# 006 Deployment

本章给出建议拓扑和验收路线。当前产物是设计和研究记录，尚无可安装的独立运行时，因此不提供虚构的安装命令、端口或配置键。

## 建议首版拓扑

一个控制实例持有本地SQLite journal、上下文索引和费用账本；一到两个受信设备上的执行节点连接harness，飞书通过渠道适配器接入。先完成单机闭环，再加入第二设备。这是降低初版复杂度的建议，并不把“多设备”偷换成“多控制实例共识”。

范围以[Philosophy](000-philosophy.md)的分层表为准：内核切片只需本机执行适配，可与控制实例同进程，不先实现远程Node Daemon；完整首版才部署第二设备和真实飞书。远程端口保留，节点代理不是单机质量验证的前置工程。

首版按单组织信任域设计，节点与逻辑Agent仍需认证和授权。跨组织互信、多控制实例高可用、离线自治合并、Temporal、共享网络文件系统上的数据库均不在首版范围。需要这些能力时另做决策和验证。

运行时应放在独立模块或仓库，通过适配层接harness。研究和设计文档现统一在`hermes-agent/docs/research`，当前分支为`multiAgent`；这不授权把运行时产品实现加入Hermes核心。Hermes接入遵守profile隔离与插件边界，不在共享进程里用全局环境变量临时切换用户状态。

## 节点与数据

节点报告身份、适配器版本、harness版本、实际可用能力与并发上限，执行绑定保存设备、会话和工作目录。密钥由各节点安全配置提供，journal只存引用及必要审计，不复制凭据到上下文或群聊。

产物使用稳定ID和内容hash。跨设备读取通过获授权的存储访问或显式传输，不假定另一台机器拥有相同绝对路径。软件工作记录仓库与commit，必要时保存未提交快照；研究记录数据版本、授权保留范围及原始证据。

活动Mission依赖的快照与检查点应纳入一致性备份。恢复数据库但缺少产物只能标unavailable，不能宣称恢复成功。备份恢复演练在闭环之后开展，不把跨地域灾备作为第一项质量实验的前置条件。

## 启动 停止与升级

| 阶段 | 必需检查 |
|---|---|
| 启动 | 数据结构版本、配置与身份有效，能力报告对应真实版本 |
| 恢复 | 先恢复合同/暂停/账本/游标/outbox，再查询未知执行 |
| 开放准入 | 未决状态被隔离、额度可用、节点能力满足当前Step |
| 停止 | 关闭新准入，保存等待与意图，请求取消并记录未确认终态 |
| 升级 | 保留旧配置与证据快照，验证数据迁移和适配兼容，不原地重解释活跃任务 |

普通停止不是“所有外部动作已撤销”。停止前后均可能有迟到回执，必须可以重复接收并去重。升级失败回滚也不能抹掉已经发生的费用或外部结果；涉及不可逆数据格式的升级需要单独恢复方案。

## 断线规则

执行节点断线后禁止给它新增工作。节点失去有效准入/租约后不再开始新turn；已经运行的turn可能继续产生费用或副作用，控制端必须标unknown，不能靠租约超时假装它停止。

在确认旧执行结束或获得明确隔离证据前，不把同一逻辑工作自动派到另一设备。首版不支持离线节点自主生成后续阶段；这减少重复执行和授权漂移。该限制不妨碍多设备分工，但必须在产品能力说明中公开。

节点重连先上传未确认回执、结果与usage，控制端按稳定ID对账，再恢复准入。传输重试不等于业务重放；实际规则见[Execution](003-execution.md)。

## 验收关卡

以下沿用V3.1的G-A到G-E关卡标识，与早期实验G0–G2分开。字母不是执行顺序：G-D质量对照先用现成harness开展，无需等待运行时建设。每一关先通过小样本，再决定扩大；本次文档工作不自动启动这些实验。

| 关卡 | 最小验证 | 通过与停止依据 |
|---|---|---|
| G-D 协作收益与成本 | 现成harness上比较强单Agent、一次审查与有界协商，选有区分度任务 | 相同配置和证据，记录质量、总/缓存tokens、召回错误、人力；无收益则收缩协作 |
| G-A 单机实际闭环 | 一个Mission、Lead＋按需同伴、Hermes/Codex、直接mention、有限阶段提案与证据采纳 | 双向正文可追溯；规划与纯消息工作均有Step/费用；接受与拒绝保留依据 |
| G-B 控制与恢复 | 持久账本、暂停与领取竞争、忙时本地排队、输入提交丢回执、计划变化、证据失效 | 重复请求不重复准入；换计划不绕过unknown；输入归属与费用/暂停跨重启保留 |
| G-C 飞书与两设备 | 真实群事件、作者/收件人、回显去重、交接、小范围订阅、按需路由、断线重连、跨设备产物 | 平台与业务状态可区分；旧执行未知时不重复派发；成员所有权与授权可复核 |
| G-E 长程连续性 | 先72小时、再7天、最终真实30天；会话轮换、来源过期、断链、改目标与暂停 | 目标与权限不漂移，保留反证和未知；实际进展、费用与恢复可核验 |

G-D不依赖建好运行时、数据库或两设备；G-A与G-B合起来构成首个运行时切片。已有早期题目满分且成本偏高，没有证明多Agent质量优势；短/长上下文小测只支持部分策略选择。没有固定要求先跑108次，扩样由不确定性、预算和任务区分度决定。

V3.2将原G-A中的完整交接验收移到G-C，与完整首版一起交付；需求没有删除。第一个切片可验收，但不得称为完整首版或已支持月级任务。正式实现前先静态核对[两条适配路径](007-architecture.md)，不能仅凭通用接口表冻结集成承诺。

## 当前能力边界

Hermes已有去重、排队、取消、观察者回放和同进程resume的局部实测，没有Gateway冷启动恢复证明。Codex已有公开通信与本地历史恢复的局部证据，但clientUserMessageId不是原生去重承诺，内部Host扩展不等于公开AppServer可接入。

真实飞书正式协议闭环、Hermes/Codex跨harness闭环、适配层统一usage、会话压缩后的关键召回和两设备恢复仍待验证。OpenClaw与DSH动态适配验证按用户要求延期；现阶段只保留静态能力研究，不用它们阻塞首版。
