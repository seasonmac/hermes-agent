# 006 Deployment：怎样部署和验收

部署方案要先回答两个问题：哪些状态由谁保存，设备失联后哪些工作还能继续。本章据此划分内核切片与多设备完整首版，并说明怎样逐步取得可信的验收证据。目前还没有可安装的独立运行时，因此这里不提供安装命令或虚构配置。

## 从单机开始，保留多设备边界

建议由一个控制实例保存本地 SQLite journal、当前任务状态、上下文索引和费用账本。内核切片中的 Hermes 与 Codex 都在本机，通过各自适配器执行工作；本地适配器可以与控制实例同进程，不必先建设远程节点代理。

完整首版再接入真实飞书和第二台设备。每台设备的执行节点负责连接本地 harness、保存待重传回执和报告状态，任务授权与业务进度仍由控制服务管理。这样可以分布执行，又不必在完整首版解决多个控制实例之间的共识。

单控制实例、SQLite、单组织信任域和一个桥接机器人都属于建议默认。跨组织互信、多控制实例高可用、离线自治合并、Temporal 以及共享网络文件系统上的数据库暂不纳入。完整首版的两设备能力仍是明确需求，不能因单机切片通过而省略。

运行时产品应位于独立模块或仓库，通过适配层接入 harness。设计文档保存在 `hermes-agent/docs/research`，不意味着产品可以加入 Hermes 核心。Hermes 插件使用公开 API，并绑定所属 profile；共享进程不能靠临时切换全局环境变量来隔离用户状态。

## 数据要能在另一台设备上找到

执行节点报告身份、适配器及 harness 版本、实效配置、可用能力和并发上限。每次执行绑定记录设备、会话及工作目录。凭据由节点安全配置提供，运行时记录和上下文只保存引用，不复制密钥到群聊。

产物采用稳定 ID 和内容 hash。跨设备读取依靠获授权的存储访问或显式传输，不假定两台机器有相同绝对路径。软件工程产物记录仓库、commit 和必要的未提交快照；研究产物记录数据版本、原始证据及保留权限。

活动任务使用的产物、合同和检查点应一起备份。数据库恢复了而关键证据丢失，系统只能报告该部分 `unavailable`。备份恢复演练放在基本闭环之后；不把跨地域灾备建设放到首次协作质量对照之前。

## 启动、停止和升级

| 阶段 | 应完成的工作 |
|---|---|
| 启动 | 检查数据结构、身份、配置和适配器能力是否匹配实际版本 |
| 恢复 | 先读合同、暂停、费用账本、输入消费与 outbox，再查询原执行 |
| 开放准入 | 对每项工作检查权限、预算、依赖和旧执行处置；无关分支可独立恢复 |
| 停止 | 关闭新领取，保存等待与执行意图，请求取消，并留下未确认终态的记录 |
| 升级 | 保留配置与证据快照，验证迁移和适配兼容，按原版本解释尚在途的工作 |

停止控制服务不等于外部执行已经停止。重启后仍可能收到迟到结果或费用，必须按原 ID 接收和去重。升级回滚同样不能抹掉已经发生的外部动作；不可逆的数据迁移需要单独恢复方案。

## 断线后先对账，再决定是否接续

节点断线后，控制服务不再向它派发新工作。节点失去有效准入后也不得开始新的回合，但已被 harness 接受的回合可能继续运行。租约到期或本地进程消失，都不足以证明远端执行结束。

例如，A 的请求已被 Codex 接受，控制服务却未收到回执。此时把同一工作交给另一设备可能造成重复执行。运行时先查询原绑定；无法确认时保留 `unknown`。只有取得终态，或完成 [003 规定的有证据处置](003-execution.md#unknown-disposition)，才考虑替代执行。处置可能允许业务接续，但未知费用仍须保留。

重连节点先上传未确认的回执、结果和用量，控制端按稳定 ID 对账，然后重新准入。完整首版不允许离线节点自行规划后续阶段；这一限制换取清晰的授权和费用归属，应在能力说明中公开。

## 分开验证协作价值与协议正确性

G-A～G-E 是发布关卡，与历史实验 G0～G2 不同。字母不表示执行顺序。G-D 可以先用现成 harness 做小样本对照，G-A/B 则验证运行时是否可靠；两条线分别报告。

| 关卡 | 最小内容 | 验收重点 |
|---|---|---|
| G-D 协作收益与成本 | 强单 Agent、一次审查、有界对等协商，使用同一任务与预算 | 质量是否有区分度；协作是否带来值得其成本的增量 |
| G-A 单机闭环 | 一个 Mission/Collaboration、两个固定成员槽位、Hermes/Codex、直接 mention、有界阶段与证据采纳 | 双向原文可追溯；首次规划和纯消息工作有 Step、授权及费用归属 |
| G-B 控制与恢复 | 暂停与领取竞争、丢回执、未知执行处置、依赖变更、证据失效和重启 | 不重复准入；不借改版绕过未知执行或验收门槛；输入、费用和暂停可恢复 |
| G-C 完整首版 | 真实飞书、两设备、交接、小范围订阅、按需 Router、断线重连及跨设备产物 | 群聊身份、所有权和平台回显正确；失联不造成重复业务 |
| G-E 长程连续性 | 先 72 小时、再 7 天，最终实际 30 天 | 会话轮换后目标和授权不漂移，反证与未知不丢失，进展、人工介入和费用可核验 |

**G-D 不硬门控协议内核。** 题目饱和或协作没有收益，不阻止 G-A/B；它影响默认执行策略和后续实验投入。质量相同而协作明显更贵时，默认使用强单 Agent，保留人工指定或合同要求的同伴审查。没有预定的“必须先跑 108 次”，扩样取决于区分度、剩余不确定性和预算。

G-A/B 构成第一个内核切片；G-C 才补齐完整首版。通过它们也不能宣称月级任务已验证，后者仍需 G-E。实验计分、预算越界和成本未知的处理见 [008](008-cookbook.md#comparison)。

## T0-P 推进了哪里

[零付费验证记录](kernel-slice-validation/preflight/README.md)给出了比源码推断更具体的证据，但仍是有限测试：

| 路径 | 已验证 | 尚未验证 |
|---|---|---|
| Codex | 安装版真实 AppServer 对合成 provider 的动态工具回调；原回合终态后关闭旧进程，新进程在同目录恢复工具并再次回调 | 未决工具 RPC、请求已接受但未终态、收费未知、目录损坏及跨设备恢复 |
| Hermes | 公开插件加载器、候选工具表、合成身份下的接受与拒绝、公开拒绝钩子 | 真实 Gateway/Agent 回合身份、完整派发权限、压缩绑定轮换、Gateway 冷恢复 |
| 费用 | Codex 合成累计计数的读取和延续 | 真实模型及辅助调用的费用覆盖、失败尾账和预算预约 |

T0-P 零付费子集的真实模型调用和模型实验 tokens 均为 0，不包括研究助手本身。合成 usage 是协议样例，不是实际账单，36 万实验软预算未因此消耗。T0-P 仍未全部完成。

接下来应先补实效工具与权限合同，再在另行获准的最短模型探针中核对真实身份和费用；在途恢复仍需单独验证。OpenClaw 与 DSH 的动态接入继续延期，不阻塞 Hermes/Codex 切片。
