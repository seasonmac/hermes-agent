# 下一轮验证口径（未执行）

2026-11-16边界验证补充：正文通道已有[三消息实测](../boundary-validation/messages/README.md)；[原生预算反例](../boundary-validation/budget/README.md)表明同配置不能保证等额预算。下面的质量筛选尚未执行，固定任务证据包保持不变。

## 条件

A：单 Agent，完整证据，独立提出并自审。
B：两 Agent 的一次审查，提出方案→同伴审查→Owner 整理，不允许额外协商往返。
C：两 Agent 可直接反提案和回应；每个参与者最多一轮实质质疑/回应，额外证据请求按同一组预算计入。不是强制争论；没有分歧可以结束。

首轮只做一个真实候选任务 × 三条件 × 一次，共三个任务运行，用于检查任务难度、轨迹可读性、预算行为。结果只作筛选；若 A 已满分且 B/C 没有新增证据，停止该任务的重复运行，换有区分度的任务，不靠继续堆样本制造收益。不要把副作用更重或证据更多只分给 B/C。

## 预检门

- 使用独立持久测试会话。主/同伴所有线程的模型、effort、基础指令、实际技能目录、工具声明、版本、证据 hash 必须记录。
- 冻结技能目录、禁用本试验不需要的插件/网页工具。角色工具差异必须列白名单：原生协作工具属于处理条件；root 独有的人类输入工具不应在无人工介入的实验中被使用。
- 不能把 include_instructions=false 等价为所有工具已裁剪，也不能把 --ignore-user-config 当成完整环境隔离。
- 同时设置同一墙钟上限、模型生成上限/生成预算（如实际入口可支持）和明确的协作组停止门槛。源码 rollout_budget 的计量可能是非缓存输入及输出或 provider units，不能命名为“严格总 token 上限”。
- 原生耗尽后宿主不得继续显式新turn或冷恢复以获得新额度；恢复前须核对已耗和未知用量。该宿主策略仍不能阻止黑盒内部在途请求，原生门槛只作附加保护。
- 保存实际全部请求用量和超额量。若没有经过验证的统一请求前预算预留，结论必须是“相同配置门槛下的观测”，不能声称严格等预算因果比较。
- 即使客户端收到了直接消息回执，也不能把它标为已读、理解或同意。需要可读的双方独立产物及回应关系；本轮候选通道为已验证的公开dynamicTools：保存发送参数、接收结果及回复关系，以独立角色的明确回应作为认可证据；原生send_message仍无公开明文。不得由协调人替角色推理或补写对话。

## 评价

每项承诺按证据正确性评分：0=错误或无依据确定断言；1=判断方向正确但缺证据/条件；2=证据与版本范围明确，且区分观测和推断。共14分。

三个事件序列各0–2分：是否定位输入/运行归属，区分请求回执与终态，并说明迟到事件与恢复的不确定性。共6分。

另列严重错误，不能被其他项目分数抵消：把客户端ID当通用幂等；把cancel回执当组内终止；把主线程累计量当全组增量；把模拟/源码当真实部署验证；把投递当共识。评分依据是已保存的观测及源码证据，不是回答长度或提了多少概念。

协作收益单独记录：同伴提出的正确新反例数；被Owner实际吸收的正确修正数；新引入错误数；未解决分歧数。新反例须能指回证据。仅相互称赞/换种说法不算收益。

成本记录：全组调用数、非缓存输入、缓存输入、输出、墙钟、准备/重试开销、实付费用（可获得时）。失败/无效运行另列，绝不默默剔除成本。上下文中含缓存的累计tokens与美元费用分开。

首轮评审可由协调助手依预先标准执行，但必须标明非独立盲评；正式选型结论需要匿名产物和独立评审。给每份产物提供等价的评审资料，不能让评审通过运行名直接知道条件。
