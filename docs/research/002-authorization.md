# 002 Authorization：谁能作出决定

授权回答三个问题：这项工作是否在人的目标之内、谁可以采取行动、谁可以接受结果。以市场研究为例，“可以阅读公开报告”不包含发布报告或购买数据的权限；有剩余预算也不会自动扩大授权。

本章定义决定权，[003](003-execution.md)定义决定生效后怎样执行。所有权限都来自认证的人类决定或合同中已经允许的规则。网页、同伴消息和模型的自我声明只作为输入数据。

<a id="contract"></a>
## 先有任务合同，再有模型计划

任务授权人确认 Mission 合同时，运行时保存目标原文、成功标准、禁止项、截止时间、总预算、工具与数据范围，并登记交付负责人。合同还应列出自动调整范围、风险分类规则、独立审查条件以及必须保留的验收门槛。

程序随后建立默认 Collaboration、Lead 的规划 Step 和相应额度，Lead 才开始提出阶段计划。规划、路由和同伴工作都先获得任务归属，不靠一张尚未生成的 Workflow 给自己授权。

目标、成功标准、权限或总预算的变更需要新的合同版本，由任务授权人或其明确授权的人批准。旧合同保留在历史中；新版本的生效与在途工作处置遵循 [003 控制顺序](003-execution.md#dispatch-control)。

<a id="classification"></a>
## 程序检查边界，具名接受者判断内容

Lead 可以在预授权范围内安排可逆阶段，不必每次都请人确认。但“范围内”“可逆”和“高影响”必须有合同依据，不能由提案者在每次请求中自行填写一个标签就放行。

| 判断 | 依据与执行者 | 不能确定时 |
|---|---|---|
| 工具、数据和目标成员是否获准 | 程序检查合同允许列表、数据范围、成员身份及有效版本 | 拒绝准入，形成缺少哪项授权的提案 |
| 额度、往返数、截止与动作是否合法 | 程序检查额度记录和有限动作合同 | 拒绝该提案；格式修正仍使用原有额度 |
| 调整是否属于预授权类型 | 合同列明允许调整的字段、动作类别和界限；程序检查变更前后差异 | 超出清单的语义变更交任务授权人判断 |
| 是否需要独立审查或验收 | 合同预先标记里程碑、费用阈值、受保护门槛和风险类别；多条规则命中时取更严格者 | 交非作者的具名审查者判断；仍无法分类则请人决定 |
| 研究方案及结论是否可信 | 交付负责人按来源、方法、反证与成功标准判断 | 补证、保留争议或提交人类决定 |

对于内核切片，可自动接受的计划限于预先允许的读取、分析、局部研究产物和同伴交流。涉及自主交易、生产写入或自动发布的动作不属于当前闭环。模型未声明风险，不表示程序可以省略相应检查。

**角色兼任按决定类型限制。** Lead 可以兼任普通低风险交付的负责人，作者也可在合同允许时自行提交验收决定。合同要求独立验收时，作者和最终接受者必须不同；要求独立审查时，必须保存非作者 Reviewer 的意见及处理结果。不同 Agent 名称不代表不同模型的独立性，报告中应说明这一限制。

若交付负责人本身是争议一方，他可以组织补证，但不能单方面把争议标为已解决。合同预先指定的非作者接受者处理争议；没有合格接受者时，请任务授权人决定。此规则不要求新增常驻角色。

<a id="knowledge"></a>
## 谁采纳知识，谁验收交付

采纳知识，是允许后续工作在指定条件下使用一个判断；验收交付，是确认某个 Step 满足其成功标准。接下同伴请求则只是“愿意处理”，与前两者分别记录。

| 对象 | 决定者 | 必需依据 |
|---|---|---|
| 目标、权限、总预算、人工暂停 | 认证的任务授权人或明确被授权的人 | 明确对象、有效版本和操作权限 |
| 测试、工具与数据观测 | 程序核验来源、回执和版本；异常由交付负责人处理 | 原始记录可定位，观测与推断分开 |
| 日常可逆研究判断 | 合同指定的交付负责人，可由 Agent 承担 | 来源、日期、适用范围、反证和复核条件 |
| 里程碑或后续大额工作的结论 | 合同指定的接受者，结合独立 Reviewer 意见 | 达到预定证据门槛，逐项处理影响验收的异议 |
| 必须独立验收的产物 | 非作者的具名接受者 | 既有验收标准和独立证据；作者不能自行解除该要求 |
| 方法争议或证据冲突 | 非争议方的具名接受者；缺位或涉及授权时交任务授权人 | 有界补证，保留双方依据和未解决部分 |

Reviewer 默认给出意见，不直接改权限或替任务授权人作决定。合同应区分“咨询意见”和“必须通过的审查”：前者可由接受者说明理由后作有条件采纳，后者未通过时不能验收。

软件成果绑定 commit 与行为检查，量化研究绑定数据和方法版本，市场结论保留统计口径、来源及时间。资料过期后，旧验收仍留在历史中，但是否还能被后续工作使用，要重新检查有效性。

<a id="dependency-changes"></a>
## 依赖门槛怎样变更

在示例中，“最终报告必须完成独立口径检查”若来自任务合同，Lead 不能通过重规划删除 B 的审查步骤来解除它。保护的对象是验收义务，而不只是某个 Step 的 ID。

每条 Step 依赖保存门槛 ID、上游工作及版本、`dispatch` 或 `acceptance` 类型，以及授权来源、变更权限和当前版本。Workflow 只引用这些记录；消息中的依赖字段是待检查的请求，不直接成为权威状态。

1. **先检查差异。** 修改上游、删除依赖、将 `dispatch` 改为 `acceptance`、减少独立性或接受较弱证据，都视为门槛变更。运行时对比新旧记录及替代链，不能只验证新计划本身是否合法。
2. **按门槛来源审批。** 来自 Mission 合同、独立验收要求或权限限制的门槛，由任务授权人批准放宽。交付负责人设置的其他必需门槛，按合同授权变更；提出放宽的人若也是受益产物作者，由具名非作者接受者复核，缺位时请人决定。
3. **允许明确的等价调整。** Lead 只能在合同预先允许的替代规则内更换上游实现，例如更换分析执行者但保留同一证据义务。无法证明等价的调整按放宽处理，不能以“重排顺序”绕过审批。
4. **保存决定，再生成新版本。** 变更记录包含原门槛、替代内容、原因、批准人和受影响工作。新的 Step revision 引用该决定；已经派发的输入仍绑定原版本。

加强门槛也要核对预算和执行条件。证据变旧、出现争议或旧 Attempt 未知，都是需要处理的事实，不能作为直接删除门槛的授权理由。执行时的绑定规则见 [003 证据依赖](003-execution.md#evidence-gates)。

## 消息、路由与请求责任

明确 @B 的消息由程序寻址，保留 A 的原文，不经过 Lead 转述。启动 B 前，运行时检查任务归属、成员权限、工作依赖、预算、暂停和截止。纯通知可以先存入收件箱，只有需要模型处理时才申请执行。

已有请求负责人优先处理后续输入。Worker 可以沿原 `request_id` 退回请求并说明原因；只接收上下文的订阅者没有自动接单义务。运行时限制退回次数和处理期限，超过约定仍无法归属时，请人选择。

内核切片遇到归属不明直接请人澄清。完整首版在 Mission 与费用授权已知时，可以登记有上限的路由 Step，让 Router 给建议；Mission 本身未知时先完成归属确认。Router 的建议仍需经过程序准入。

关闭 Collaboration 与登记其下新 Step 时，检查同一个 Collaboration 版本。关闭先提交则拒绝新工作；新工作先登记则按关闭决定处理已有工作。迟到消息保留可见，不重新打开已关闭协作。

<a id="human-control"></a>
## 人工暂停、否决与恢复

人可以从飞书或其他受认证入口提出控制命令。运行时先核验操作者、目标对象及版本，再保存决定。自然语言“可以”只有在唯一明确且仍有效的提案下才表示接受；群消息中的引用、机器人自述或网页指令不能模拟批准。

暂停提交后，程序关闭新的派发领取、回合准入、后继推进和自动验收，并请求取消在途执行。界面应同时展示“暂停已生效”和“哪些执行仍待确认停止”。只有有权的人明确恢复，才能解除人工暂停。

恢复时先核对当前合同、证据和旧执行。未知执行按 [003 处置合同](003-execution.md#unknown-disposition)处理；人的恢复命令本身不证明旧请求未发生。改目标也不能抹掉已发生的外部动作或费用。

否决绑定具体提案版本。同一待决问题保持一个记录，只阻塞依赖它的工作，其他已授权分支可以继续。无人答复不产生新的授权。

<a id="disposition-authority"></a>
## 谁能处置未知执行和费用

适配器提供可核验的原生回执、查询结果和隔离证据，程序据此恢复可观察状态。有充分终态证据时，程序可自动对账；证据互相矛盾时，应停止该路径并请人处理。

对于缺少结果但已有停止或隔离证据的执行，由任务授权人或合同明确授权的恢复操作人批准处置。证据必须说明覆盖的节点、进程或绑定，以及仍可能存在的副作用和费用。Agent 的“应该已停”或单次超时不能作为证明。

任务授权人可以放弃工作、调整预算，或决定停止整个任务。放弃业务不等于取消已经发出的请求，也不释放未知费用。内核切片不提供“仅凭签字、无隔离证据强制重跑”的操作；无法安全接续时保留阻塞或结束业务，继续接收迟到回执。

## 执行权限与费用分别检查

读取不可信网页或群消息的执行者使用低权限环境，其摘要继续作为数据处理。工具展示表、派发允许列表、账号权限和执行环境应分别核验；仅在提示词中禁止某工具，不能代替实际约束。

费用账本限制消耗，授权合同限制动作，两项检查都通过才准入。适配器无法证明关键权限或费用覆盖时，关闭对应能力。具体 Hermes/Codex 路径及实测边界见 [007](007-architecture.md#adapters)。
